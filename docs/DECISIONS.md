# Decisions (permanent unless a new entry supersedes)

| # | Decision | Reason |
|---|----------|--------|
| 1 | Next.js (App Router) + TypeScript + Tailwind, single deployable app | Common, well-supported default stack; route handlers give a secure server for the API key without a separate backend. |
| 2 | **Device-local storage (localStorage) instead of Supabase** | A hosted database such as Supabase was an option, but the project brief requires a runnable app with no external accounts, and minors' data is safer not stored on a server. Storage sits behind `services/storage.ts` so a database can replace it later. |
| 3 | Anthropic API (Claude) for conversation + report, model configurable via `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`) | Strong conversational + structured-output quality; key stays server-side. |
| 4 | Browser Web Speech API for STT and TTS | Free, no extra credentials, real voice I/O. Limitation: Chrome/Edge/Safari only for recognition; may use a vendor cloud service (disclosed). Typed fallback always available. |
| 5 | Half-duplex turn taking (recognition paused while coach speaks) | Prevents the mic hearing the coach's own voice. |
| 6 | Pace/pause metrics from Web Audio voice-activity timing + recogniser word counts | Measurable without a paid service; limitations documented in the report. |
| 7 | MediaPipe Tasks Vision (face landmarker + pose landmarker) in-browser | Pretrained, on-device, no video upload. Models downloaded by `npm run setup:vision`. |
| 8 | No pronunciation score | Web Speech gives no phoneme data; only an approximate "words the recogniser struggled with" list is shown, labelled approximate. |
| 9 | Dev mode when no API key: scripted coach, metrics-only report, clearly labelled | Required by brief; must not pretend AI works. |
| 10 | Hard 20 minute/day cap, enforced in the UI and session timer | Brief requirement. |
| 11 | Hand-rolled SVG charts, no chart library | Fewer dependencies, enough for trends. |
| 12 | Two models: fast one for conversation (`ANTHROPIC_CHAT_MODEL`), stronger one for the report (`ANTHROPIC_MODEL`) | Voice conversation is latency-sensitive; the report is not. |
| 13 | MediaPipe uses the **CPU** delegate with a 30 s load timeout | GPU delegate creation hung in headless Chromium; ~4 fps analysis does not need a GPU; a hang must never block a session. |
| 14 | Content-Security-Policy `connect-src 'self'` | MediaPipe's runtime pings `odml.pa.googleapis.com` with usage logs; found by an e2e test. Blocking it makes the "video never leaves the device" claim true. |
| 15 | Opening coach message is fixed text (no model call) | Instant start, works in both modes, and keeps the student's name off the server. |
| 16 | Report quotes verified server-side against the transcript | Prevents the model from showing examples the student never said. |
| 17 | Trends need 2+ completed sessions and appear silently (no message while there is too little data) | Two points are the minimum to compare; the owner asked for no explanatory text. |
| 18 | **Groq `openai/gpt-oss-120b` is the default LLM**, behind `server/llm.ts`; Anthropic stays as an alternative (`LLM_PROVIDER`) | Owner's chosen stack. One provider layer keeps routes unchanged and lets tests stub it. Reasoning is hidden (`include_reasoning: false`) and effort is `low` for chat, `medium` for reports. |
| 19 | **Sarvam (STT) and Cartesia (TTS) are called only from server proxy routes** (`/api/voice/stt`, `/api/voice/tts`) | Keys never reach the browser. Routes check origin, rate-limit and validate type/size; audio is forwarded and discarded. The Cartesia voice ID is server-side config. |
| 20 | **Silero VAD in the browser splits speech into segments; each segment is transcribed separately** | Sarvam's REST endpoint accepts under ~30 s per request; segments (split at 25 s if longer) give live text while the student talks, and VAD timestamps give real pause and thinking-time measurements. |
| 21 | Answer ends after ~3.2 s of quiet (and never while a segment is still being transcribed), or on "I'm done speaking" | The owner's report that voice answers were cut off. Longer patience beats cutting people off mid-thought. |
| 22 | Voice failures degrade, never dead-end: Cartesia to browser voice, Sarvam to browser recogniser, then a "Try voice again" button; typing and End session are always available | The previous design permanently disabled voice after a recogniser error. |
| 23 | Pressing End session keeps the answer being spoken | Ending mid-sentence should not lose what the student said. |
| 24 | **Pipecat + SmallWebRTC not adopted** | They need a separate Python server. The same Sarvam/Groq/Cartesia/Silero stack is reached from the existing Next.js app over HTTP; revisit if sub-second full-duplex conversation becomes a requirement. |
| 25 | Report is organised as Reading, Answering, Camera, each with what went well / what to improve / how to improve; numbers move into a collapsible section | The owner asked for feedback on how they performed while reading and answering and what to fix, including webcam behaviour. Coaching text is rule-based from measurements (and AI for answers and reading), and never infers emotion. |
| 26 | Two-phase session: Phase 1 read the passage out loud (primary action), Phase 2 live conversation about it; 20 minutes per day maximum | Owner's required structure. Reading aloud is the main action but never blocks the session when voice is unavailable. |
| 27 | Report wording is very simple English (short sentences, everyday words, always what to do), and every problem comes with a fix | Owner request; also better for young students and learners. The AI prompt enforces it and a unit test rejects jargon in the rule-based text. |
| 28 | "Instead of this, say it like this" examples: from the AI (quote must be verbatim, verified server-side) or, without AI, worked out from the student's own words (fillers and repeats removed, or a fill-in frame for a short answer) | Shows the student exactly what to say instead, without inventing ideas. |
| 29 | Report download is made on the device with jsPDF (PDF) or plain text from one shared document model | Nothing is uploaded; both files always say the same thing; the model is unit-tested and a real PDF is checked in e2e. |
| 30 | The look is "Sunrise": cream page, plum text, a peach-to-coral gradient on the main card, pill buttons, round cards, speech-bubble answers. Fonts are Fredoka (headings) and Nunito (text), self-hosted. | Chosen by the owner from several options. It reads as friendly and clearly different from a default app template. All colours live in `src/app/globals.css`. |
| 31 | If the AI-written feedback fails, the report page offers **Try again**, which asks again from the saved answers | A network or service failure should not leave a student without feedback. It only appears when answers were saved and the app is not in development mode. |
| 32 | The site uses the full screen width (header and pages), with the logo at the far left and the tabs across the top. Text-heavy flows (reading, conversation, forms) keep a readable column. | The owner found the centred, narrow layout looked like a phone app, not a website. |
| 33 | Light theme only. There is no dark mode or theme switch, and the page tells browsers not to force a dark version (`color-scheme: light`). | The owner wants the app shown only in the light Sunrise look. An earlier dark mode was removed. |
| 34 | The report is short by default: one good point and one fix per part, two "say it like this" examples, two exercises. The rest is behind "More detail". The AI is asked for fewer, shorter items, with low reasoning effort and a smaller answer budget. | Owner request: the report was too long and too slow. Reports now take about 3 seconds instead of about 7. |
| 35 | While the report is made the screen shows a percentage and a progress bar. The number is an estimate that moves steadily and reaches 100% when the report is ready. | Owner request. The real wait is short and not measurable in steps, so the bar eases forward rather than claiming exact stages. |
| 36 | The Library shows only the modules for the subject saved in the profile. Subject, difficulty and goal are chosen once at the start and changed only in the Profile, whose sections open when tapped. The practice goal is never read from the address. | Owner request: no choosing on every page. Goal-specific questions are mixed into the coach's questions so the practice changes with the goal. |
| 37 | Speech recognition and the coach's voice use English (India) only. Older saved accent choices are ignored. | Owner request. |
| 38 | The camera models load in parallel, and start loading as soon as the camera box is ticked. | So the camera is ready at the start of the session instead of loading after it begins. |
| 39 | There is one module for every subject, level and goal (8 x 3 x 5 = 120). The Library shows the 3 for the student's subject and goal, own level first. | Owner request: modules must change with the problem the student wants to fix, not only the subject. Each module has its own passage, a different kind of activity for its goal, and 7 questions ordered easy to hard. |
| 40 | The coach's questions go from easy to difficult: questions 1 to 3 easy, 4 and 5 medium, 6 and later hard. The rule is in the coach prompt and the screen shows "Question 3: Warm-up question". | Owner request. Checked by the quality test (the AI marks how hard each question is, in shuffled order). |
| 41 | While the student speaks, the words shown live come from the browser's own speech recogniser; the text that is saved and measured still comes from Sarvam. | Sarvam only answers after a pause, so the owner saw the words late. The live words are for display only, and any failure of the browser recogniser is ignored. |
| 42 | In the short report, points about the reading and the answers' numbers come from the measurements, not from the AI's words. Empty praise ("you answered every question") and "say it like this" templates with blanks are never shown. The AI's quote is shown next to each fix. | The first quality test found the AI saying the passage was "read correctly" when words were missed, and praising off-topic answers. |
| 43 | The AI is given "facts found by software" (short answers, "I don't know" answers, fillers, repeated plain words, unread part of the passage) and a priority order for what to talk about first. | So it spends its two fix points on the biggest problems instead of small ones. |
| 44 | A quality test (`npm run eval`) runs made-up sessions with planted mistakes through the real AI and marks the results. A different AI model (Qwen) does the marking. | The owner asked to see how well the feedback really works. See docs/EVALUATION.md. |
| 45 | The conversation uses `openai/gpt-oss-20b`; the report keeps `openai/gpt-oss-120b`. A rate-limit answer from Groq is retried after a short wait, but not when Groq asks for more than 20 seconds. | The free Groq key allows 200,000 tokens a day per model. Two models give two allowances, the small model is faster for talking, and the quality test showed it is not accurate enough for the report. |
| 46 | If the coach asks more than one question in a reply, everything after the first question is dropped. | The student answers by voice and cannot tell which question to answer. The quality test found 1 reply in 3 with two questions. |
| 47 | All 120 modules were rewritten to a written guide (docs/CONTENT-GUIDE.md) that tests enforce: each level reads at its own level and is clearly harder than the one before, every question is one question, the seven questions go from easy to hard, and each goal practises its own skill (retelling, explaining, using words, defending a view, answering interview questions). | A check of the first version found 121 of 880 quality checks failing: 40 passages at the wrong reading level, 34 modules with repeated question openings, 21 with badly shaped questions and 19 that did not fit their goal. The facts in the passages are written by AI and still need a teacher to read them. |
| 48 | There is a separate set of modules for each age group (under 13, 13 to 17, 18 and older): 8 x 3 x 5 x 3 = 360. The level is about the English; the age group changes the people, topics and tone. The earlier 120 modules became the 13 to 17 set. Old saved sessions still open. | Owner request: modules must differ when the age group changes and the other three choices stay the same. A test requires the three versions to have different titles, stories and questions. |
| 49 | A student can choose "Not sure yet" for the subject, the difficulty and the goal. The Library then shows a small mix to try (rules in `modulesForProfile`), and the recommendation uses recent sessions. | Owner request: someone who does not know what to choose must still get relevant modules. |
| 50 | The report page is in boxes (reading, conversation, face and body). Download gives the same report as a one-page black-and-white PDF (the writing is made smaller until it fits). | Owner request. The earlier "PDF only" page was replaced because the boxes were easier to read. |
| 51 | Reading is analysed word by word: skipped parts, where the student stopped, and words the recogniser heard as another word. Word parts come from spelling rules, with a Hear it button. | Owner request ("what part I skipped and what pronunciation was wrong"). There is no pronunciation dictionary, so this is a guide, not a pronunciation mark. |
| 52 | After a pause the coach asks "Are you done?" and acts on yes, more, or end. A short reply is recognised by the browser (fast) with command words as hints for the cloud recogniser. Speaking over the coach interrupts it (can be turned off). | Owner request for a smoother conversation. Interrupting is not tested with a real microphone. |
| 53 | Face looks are smoothed over a moment, each must last two frames or more, and a person's resting face is allowed for (the quietest fifth of the session, up to a limit). Eyes looking down is measured. | The first version used single frames and fixed limits, which can misjudge a face that sits a little tense. Still not validated on many real faces. |
| 54 | The reading report always says how much was read, which parts were skipped, how clear the words were ("your pronunciation can be clearer") and how fast the student read, and never says there is nothing to fix when part of the passage was not read. While reading, words get a green (read), red (skipped) or orange (not clear) line. | Owner report: a half-read passage got "nothing to fix". Coverage is counted to the last word the student reached; a start of four or more skipped words is shown as skipped. |
| 55 | The coach answers any harmless question first, even off the topic, then asks one question. "Next question", "repeat" and "hint" are spoken commands that skip the "Are you done?" step. | Owner request. The commands are matched at the end of what the student says, so the word "next" inside an answer does not move the lesson on. |
| 56 | Modules are written as short professional lessons: no made-up characters, real explained content, a clear topic title, and seven questions that go from recall to opinion. Each module also has seven answer hints (what a strong answer contains) that only the server reads: they live in `src/features/content/hints` and are kept out of the browser code, which also makes pages load faster. | Owner feedback: stories about named people ("Imran and the Pump Factory Internship") did not look professional. Facts still need a teacher's check. |
| 57 | The coach is told the place of the next question (`ladderIndex`), counted by the app. A question from the student, silence and unclear speech do not move it; an answer or a skip does. | Without it, a student's question or a skip shifted every later question. |
| 58 | The first quiet moment gets a short spoken line from the app, not a new coach message from the AI; the AI hint comes the second time. After "wait" or "let me think", waits are longer. An answer that ends in the middle of a sentence is waited for longer. No reply to "Are you done?" counts as yes only for a full answer. | Owner feedback: the coach spoke on its own and cut in. |
| 59 | The report has a "Your words" box (filler words with counts and the question they were most in, and wrong words shown as "You said / Say"), a tile for it, and a three-step plan for next time. Wrong words come from the AI (checked against the transcript) and from a fixed list of common mistakes. | Owner request: fillers and wrong words must be in the report. The list is small on purpose so it rarely flags a correct sentence. |
